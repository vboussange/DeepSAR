# Scale-Bias Investigation

Date: 2026-06-05
Dataset: `ceacce0`
GIFT dataset: `418c563`

Status: historical diagnostic note. The finite-versus-asymptotic evaluation
requested below is implemented in
`scripts/experiments_3rd_rev/gift_asymptote_evaluation.py`; final revision
results report the asymptotic audit explicitly.

## Observed Behaviour

Exploratory MuScaRi predictions show a scale-signed residual pattern: the model
overpredicts richness in small spatial units and underpredicts richness in large
spatial units. This note summarizes likely mechanisms and small experiments to
test them.

The key interpretation is that this is unlikely to be explained only by limited
neural-network capacity. The current `architecture_screen` weakens the simplest
"model cannot handle the richness range" explanation, but does not remove a
more fundamental identifiability problem: total richness `S_T` is inferred from
finite-effort EVA samples and is never directly supervised during training.

## Relevant Pipeline Facts

The manuscript defines MuScaRi as a neural network that maps spatial-unit
features `X` to the parameters of a monotone saturating rarefaction curve. The
training loss is finite-effort MSE on observed richness:

```text
M_theta(a_i, X_i) -> S(a_i)
```

The target quantity for maps and SARs is the asymptote:

```text
S_T = lim_{a -> infinity} M_theta(a, X)
```

In the implementation, the asymptote is the `c` output of the feature network
(`muscari/muscari.py`). Thus the model can obtain a good finite-effort fit while
still miscalibrating `S_T`, especially when training samples are far from
saturation.

Important implementation points:

- `observed_area` enters the Weibull branch through `log_observed_area`.
- `sp_unit_area` enters as a feature through `log_sp_unit_area`.
- Training uses `MSELoss` on richness scaled by `MaxAbsScaler`.
- The current training/evaluation path evaluates GIFT through the ordinary forward pass on a
  dataloader, with `observed_area = sp_unit_area`, rather than through
  `predict_sr_tot()`. This is finite full-area prediction, not the asymptotic
  `S_T` evaluation described in the manuscript.
- Random sample generation chooses spatial units, then samples a log-uniform
  number of EVA plots within each unit. Median sampled coverage is extremely
  small relative to the spatial unit.

## Diagnostic Anchors

Quick diagnostics on `ceacce0` and the pre-fix absolute-effort checkpoints gave:

- EVA train median `observed_area / sp_unit_area`: about `6.6e-7`.
- EVA test median `observed_area / sp_unit_area`: about `3.7e-7`.
- GIFT `observed_area / sp_unit_area`: exactly `1.0` by construction.
- Spearman correlation in EVA train:
  - `log_observed_area` versus `sr`: `0.902`.
  - `log_sp_unit_area` versus `sr`: `0.549`.
  - `log_sp_unit_area` versus `log_observed_area`: `0.468`.
- Pre-fix absolute-effort finite-effort EVA test residual slope versus
  `log_sp_unit_area`: about `-0.062`.
- On GIFT, the current ensemble overpredicts the smallest area quintile and
  underpredicts middle-to-large units.

For GIFT, the finite full-area and actual asymptote predictions differ:

```text
finite full-area evaluation: mean RMSE about 498
true asymptote-head evaluation: mean RMSE about 515
```

The actual asymptote evaluation shows stronger small-unit overprediction.

## Ranked Hypotheses

### H1. Weak asymptote identifiability

This is the leading hypothesis. EVA training labels observe species richness at
small finite efforts, while `S_T` is never observed. With sampled coverage often
below `1e-6`, many combinations of asymptote and curve shape can explain the
same observed finite-effort richness. The network may fit interpolation well but
learn an area-conditioned asymptote that regresses toward the median scale.

Prediction: corrected `predict_sr_tot()` evaluation should show scale-signed
GIFT residuals even when finite-effort interpolation is strong.

### H2. Observed-effort shortcut and area confounding

Observed area is much more predictive of training richness than spatial-unit
area. Because observed area and spatial-unit area are still moderately
correlated, the model can use observed effort as the dominant signal and learn
spatial-unit area as a weak correction. This creates the right conditions for
small areas to be assigned too high an asymptote and larger areas too low an
asymptote.

Prediction: residuals should align more cleanly with the joint
`log_observed_area x log_sp_unit_area` surface than with either variable alone.
At fixed low observed effort, large units should be particularly underpredicted.

### H3. Coverage distribution shift

EVA training mostly covers tiny fractions of each spatial unit. GIFT evaluation
sets `observed_area = sp_unit_area`, and map/SAR use cases ask for `S_T`.
Therefore the model is evaluated in an effort/coverage regime not represented by
training labels.

Prediction: adding high-coverage samples generated by selecting all plots within
small-to-medium spatial units should reduce scale-signed residuals, even without
changing the architecture.

### H4. Parametric and scaling mismatch

The manuscript describes a monotone saturating Weibull model. Before the
2026-06-05 parameter-transform fix, the implementation only enforced `d < c`;
the shape parameter `b` was unconstrained and both the lower richness and the
asymptote could be negative. The current implementation constrains `b > 0`,
`c > 0`, and `0 < d < c`. A remaining concern is that `log_observed_area` is
MinMax-scaled and then transformed again inside the Weibull branch, which may
make the learned curve parameters less interpretable.

Prediction: a stricter parameterization using explicit positive shape/scale
parameters and a well-defined effort coordinate should improve asymptote
stability more than interpolation RMSE.

### H5. Sampling-process mismatch

Training spatial units are generated around EVA plot locations and inherit EVA
plot-density biases. GIFT units are administrative inventories with different
geometry, sampling history, and species-list completeness. Area can become a
proxy for these mismatches.

Prediction: residuals should correlate with EVA plot density, number of EVA
plots inside the GIFT unit, and geographic region even after controlling for
area.

## Methodological Issue To Fix First

Separate three quantities explicitly:

1. Finite-effort EVA interpolation:
   `predict_sr(df)` at observed EVA `observed_area`.
2. Finite full-area GIFT prediction:
   `predict_sr(df)` with `observed_area = sp_unit_area`.
3. True asymptotic richness:
   `predict_sr_tot(df)`.

The current training/evaluation path reports GIFT as extrapolation but evaluates quantity 2,
not quantity 3. The manuscript and maps emphasize quantity 3. Before choosing a
final architecture, all result tables should report both GIFT finite full-area
and GIFT asymptote metrics, or clearly justify one of them.

## Small Experiments

### Experiment 1. Corrected evaluation audit

No retraining. Use existing architecture-screen checkpoints.

For each architecture variant and fold, compute:

- EVA interpolation metrics with `predict_sr()`.
- GIFT finite full-area metrics with `predict_sr()`.
- GIFT asymptote metrics with `predict_sr_tot()`.
- Residual slopes and area-bin median biases for each mode.

Decision criterion: if `predict_sr_tot()` has a stronger small-large residual
than finite full-area prediction, prioritize asymptote calibration in the next
experiments.

### Experiment 2. Residual surface diagnostic

No retraining. For EVA test samples and GIFT units, stratify relative residuals
by:

- `log_sp_unit_area`.
- `log_observed_area`.
- `log_observed_area - log_sp_unit_area`.
- EVA plot density inside the spatial unit.
- Environmental heterogeneity features.

Decision criterion: if residuals remain scale-signed within fixed observed
effort or fixed coverage bins, the bias is not only a marginal sampling-effort
artifact.

### Experiment 3. Area-effort balanced loss

One-fold smoke training first, then all folds only if promising.

Weight training samples by inverse frequency in 2D bins of
`log_sp_unit_area x log_observed_area`, or build batches with balanced bins.

Decision criterion: the fix is promising if the GIFT asymptote residual slope
moves toward zero with no large loss in EVA interpolation RMSE.

### Experiment 4. Coverage-aware effort coordinate

Train a compact variant where effort is represented as relative coverage:

```text
log_coverage = log_observed_area - log_sp_unit_area
```

or as both:

```text
log_observed_area, log_coverage
```

Do not rely on `log_observed_area / log_sp_unit_area` alone, because this ratio
is hard to interpret and compresses units nonlinearly.

Decision criterion: improved GIFT area-bin calibration with comparable EVA
interpolation performance.

### Experiment 5. Same-unit multi-effort samples

Generate multiple samples for the same spatial unit:

- low-effort subsets,
- intermediate subsets,
- all contained EVA plots.

This makes the model see partial rarefaction curves for fixed `X`, rather than
one noisy point per spatial unit.

Decision criterion: improved asymptote stability and lower ensemble spread in
`S_T`, especially at small and intermediate spatial units.

### Experiment 6. Known-truth synthetic rarefaction

Simulate spatial communities with known `S_T`, sample them with EVA-like plot
layouts and plot areas, and train MuScaRi on the generated finite-effort labels.

Decision criterion: if the current architecture reproduces the same small-large
bias under known truth, the failure is intrinsic to the training objective or
parameterization. If not, the dominant cause is probably EVA/GIFT distribution
mismatch.

## Candidate Fixes

Start with fixes that preserve the current style and keep changes local:

- Keep the standalone corrected GIFT asymptote audit synchronized with final artifacts.
- Report finite full-area and asymptote metrics separately.
- Add residual diagnostics by area, effort, coverage, and plot density.
- Try area-effort loss reweighting before changing architecture.
- Add same-unit multi-effort samples for a limited one-fold experiment.
- Revisit the effort coordinate used inside the Weibull branch only after
  diagnostics show that weighting and data generation do not resolve the bias.

Avoid large framework changes. The most valuable next step is a small diagnostic
script in this folder that loads existing checkpoints and writes bias-by-bin
tables for all architecture variants.
